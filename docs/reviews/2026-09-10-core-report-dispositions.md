# Legion Core report dispositions — 2026-09-10

This ledger closes the one-time catch-up over
[issue #145](https://github.com/Opus-Aether-AI/legion-core/issues/145),
[#176](https://github.com/Opus-Aether-AI/legion-core/issues/176),
[#187](https://github.com/Opus-Aether-AI/legion-core/issues/187),
[#192](https://github.com/Opus-Aether-AI/legion-core/issues/192),
[#193](https://github.com/Opus-Aether-AI/legion-core/issues/193),
[#194](https://github.com/Opus-Aether-AI/legion-core/issues/194), and
[#200](https://github.com/Opus-Aether-AI/legion-core/issues/200). Closing a
research report means every major proposal has a durable disposition; it does
not mean that every speculative capability belongs in this release.

The catch-up deliberately prioritizes pre-spend admission, truthful receipts,
bounded child execution, monotonic consumer updates, and release metadata.
Large new subsystems remain deferred with an explicit acceptance contract so a
future weekly run can detect changed evidence without rediscovering the work.

| Source | Finding | Disposition | Evidence in this change or current main | Residual acceptance criterion |
|---|---|---|---|---|
| #145 | Direct and brokered children had no universal execution lease or complete process-tree cleanup. | **Implemented** | Executor registry defaults and lower-only overrides now flow through every adapter, review/resume, Sandcastle, and the broker. The monotonic supervisor emits a typed `timed_out` sidecar and removes disposable Git state. | Silent, noisy, detached, nested, cancellation-race, and just-under-deadline fixtures must remain deterministic; the primary convergence lifecycle remains uncapped. |
| #176 | Lifecycle-hook commands were accepted and documented without runtime execution. | **Deferred** | No new hook surface is activated in this catch-up. | A typed dispatcher must execute supported hooks exactly once, preserve built-ins when absent, distinguish replacement from augmentation, and fail the owning stage on timeout or malformed receipts. `telemetry_sink` stays reserved until it has a stream contract. |
| #176 | The owned session log lacked collision resistance, cross-process sequencing, deep redaction, corruption handling, size bounds, and a production reconstruction gate. | **Deferred** | The session log is not promoted as authoritative evidence by this change. | Concurrent-writer, colliding-ID, interior-corruption, truncated-tail, nested-secret, schema-invalid, and large-payload fixtures must pass before activation. |
| #176 | ACP v2 cancellation, permission, notification, stderr, deadline, and correlation behavior was incomplete. | **Already implemented; activation still gated** | [PR #177](https://github.com/Opus-Aether-AI/legion-core/pull/177) repaired request/notification separation, option selection, bounded stderr, cancellation, correlation, and cleanup. Every executor still declares `acp = false`. | An executor may enable ACP only after its live initialize/prompt/update/cancel/permission canary and advertised capability matrix pass against the pinned protocol revision. |
| #176 | Core-update PRs overstated repository-owned validation and the Code caller used a mutable reusable-workflow ref. | **Partially implemented** | The reusable workflow now states explicitly when no consumer validation command was configured and verifies the exact draft PR head. | Legion Code must pass a repository-owned validation command and advance an immutable workflow reference with the Core pin; the release tag, package, and source SHA must be provenance-bound before mutation. |
| #176 | Public capability claims could outrun executable reachability. | **Deferred** | ACP remains disabled and this ledger does not call parsed hooks or the session log active. | A source-controlled scaffold/experimental/active admission table must bind every active claim to an entry point, negative-path test, and artifact contract. |
| #187 | DeepSeek `read-only` was a post-run diff check, not preventive confinement. | **Implemented (fail closed)** | The registry advertises only `workspace-write`; preflight rejects `read-only` before resolving or launching `dsh`. | Re-enable only after an exact-version adversarial fixture proves full enforcement outside allowed roots. |
| #187 | DeepSeek claimed out-of-band task/model behavior that its provider launch did not perform. | **Implemented as a truthful restricted contract** | DeepSeek declares argv transport, rejects ineffective `--model` overrides before launch, records unknown effective identity, and bounds every child with the lease. | A future out-of-band profile must keep task bytes out of argv, authenticate the task file, report the observed model/config digest, and pass an `ARG_MAX` fixture. |
| #187, #200 | Versioned Core dispatches accumulated separate, potentially stale update PRs. | **Implemented** | The reusable updater serializes per consumer, maintains `chore/legion-core-latest`, compares checked-in and candidate SemVer, emits `superseded`/`already_current` receipts, uses explicit force-with-lease, and keeps the exact candidate PR in draft. | Out-of-order/replayed dispatches must never lower the candidate or overwrite a newer head; merge remains human-only. |
| #187 | Unreported usage/cost was indistinguishable from measured zero. | **Implemented** | `legion.attempt.v1` separates nullable values from `known`, `estimated`, and `unknown` provenance; adapters use provider evidence only, and DeepSeek remains unknown instead of free. | Aggregates and routing must preserve unknown counts and must not make cheapest-model claims across unknown candidates. |
| #187 | Scheduled Code vendoring used movable actions and freshly resolved validation dependencies. | **Implemented in the companion Code catch-up** | The Code workflow uses full action SHAs, exact Python dependencies, bounded work, structured failures, and draft-only partial results. | Dependency changes remain reviewable pin diffs; no unattended merge is introduced. |
| #192 | Root, package, marketplace, and plugin licence metadata contradicted each other. | **Implemented** | `.claude-plugin/license-policy.json` owns `BUSL-1.1`, the exact `LICENSE` digest, change date, and change licence. Package, marketplace, every plugin manifest, CI, release publication, recovery, and packed-tarball tests now enforce it. | Any future licence-policy change must update the explicit policy and digest in a reviewed change; inconsistent artifacts fail before publication. |
| #192 | Benchmark comparisons lacked a content-addressed measurement identity. | **Deferred** | Existing benchmark gates are not re-labelled as proof of cohort comparability. | The resolved corpus, ordered inputs, graders, validators, routes, models/effort, source state, and runtime versions must share one algorithm-versioned identity; mismatches return `incomparable` before deltas. |
| #192 | Core releases did not surface material policy changes at the Code admission boundary. | **Deferred** | Licence coherence is now enforced inside Core, but the dispatch payload remains the v1 version/tag/SHA contract. | A signed or provenance-backed release manifest must bind package integrity, source/tag, licence identifier/digest, and material-change reasons; Code must render and acknowledge policy deltas. |
| #192, #200 | Raw task evidence lacked a unified privacy, retention, and purge lifecycle. | **Deferred** | This change adds no claim that current local spans are content-minimized. | Add explicit metadata/redacted/full modes, digest and size fields, owned artifact retention, recursive secret fixtures, targeted purge, and an evidence-fidelity signal for learning. |
| #192, #194 | One model field and one terminal span could misattribute provider fallback, usage, and cost. | **Implemented at the attempt boundary** | Every provider attempt gets requested/effective model and effort, config/cache lineage, independent usage/cost provenance, output-started state, typed failure, and terminal status. Same-vendor fallback preserves separate attempt files. | Provider-internal substitution remains unknown when the provider does not emit it; aggregate reports must reconcile child attempts and never infer missing effective identity. |
| #193 | Successful lifecycle stages could buffer and persist unbounded stdout/stderr. | **Deferred** | Child runtime is now bounded, but successful stage byte volume is not yet a streaming/spill contract. | Stream to private files, retain bounded head/tail plus counts/digests, enforce inline and hard caps, terminate the process tree on overflow, and benchmark a 100 MiB fixture under a predeclared RSS ceiling. |
| #193 | Broker write isolation did not imply repository-only read privacy. | **Deferred; current scope remains host-readable** | This change does not relabel mutation containment as read isolation. | Add a receipt-level `read_scope`, copy only required runtime auth, deny unrelated repositories/home data on Darwin and Linux, and pass symlink, `/proc`, alternate-path, and inherited-environment bypass fixtures. |
| #193 | A disconnected one-hop client could not safely retrieve a completed broker result. | **Deferred** | The broker remains authenticated, isolated, single-use, and now time-bounded; it is not advertised as replay-safe. | Add a stable request ID/digest and atomic private terminal receipt; identical terminal replays return the same result without spawning or duplicating telemetry, while changed/in-flight payloads fail closed. |
| #193 | Legion Code could return success after an active bridge refresh failed. | **Deferred to the Code repository** | The companion Code change focuses on reported open issues and vendoring reliability; it does not silently redefine refresh exit codes. | Emit one `legion.refresh.v1` receipt with old/new commits and component states; required bridge failure returns a documented nonzero partial/failed result while optional integrations remain explicit. |
| #193 | OTLP export and exact aggregation loaded complete histories into memory. | **Deferred** | No scalability claim is added. | Iterator-driven count/byte batches, acknowledged cursors, bounded scans, and explicit exact/approximate percentile modes must pass a one-million-span memory and delivery benchmark. |
| #194 | Headless Fable could consume premium usage credits without explicit admission. | **Implemented** | Fable model patterns require explicit premium-credit consent in preflight; blocked calls produce typed no-spend evidence and only already-declared fallback remains eligible. | Seat/payment details never enter telemetry, and zero provider invocations occur without explicit policy or operator consent. |
| #194, #200 | Model/CLI compatibility was not a pre-spend executor contract. | **Implemented as an admission foundation** | Registry fields now cover executable/version probes, supported and known-bad ranges, config fingerprints, model/effort/sandbox/transport capabilities, billing, cancellation, and lease defaults. Cached identities bind executable and relevant configuration. | Populate exact known-bad/model-version canaries as evidence appears. Unverified versions remain `untested` and cannot be presented as certified support. |
| #194 | Unattended Claude runs could wait for prompts or rely on dangerous bypass. | **Implemented** | Workspace-write uses fail-closed noninteractive permission handling; permission refusal is typed, non-retryable, and never escalates to dangerous bypass or another provider after output starts. | Permission-requiring fixtures continue to terminate without side effects or fallback. |
| #194 | Appended Claude system instructions remained on argv. | **Deferred** | Task payloads are out-of-band where the provider supports it, but appended system text is unchanged. | Stage prompts in a private authenticated file, retain only digest/size, and remove it on success, failure, signal, and fallback; an over-`ARG_MAX` sentinel must stay absent from argv/logs/spans. |
| #194 | Legion Code lacked a skills-only Cline Agent Plugin projection. | **Deferred to the Code repository** | No workspace plugin is generated by this Core change. | A transactional, opt-out user package must expose exactly the selected profile, track only owned files, reject malformed packages before activation, and preserve user-owned packages on uninstall. |
| #200 | The live Sol migration route lacked a paired, blinded Terra/Sol experiment. | **Deferred; routing expansion prohibited by current policy** | The route remains a narrow migration pilot; this change does not claim Sol quality or savings from unmatched telemetry. | Pre-register at least 30 comparable pairs across three migration classes with content-addressed inputs, randomized order, blinded independent grading, thresholds, invalid-pair counts, cost, tokens, attempts, and p50/p95 latency. |
| #200 | Recursive children could request broader authority than the parent intended. | **Deferred; lease handles runtime only** | Nested leases cap time and the existing broker retains authenticated isolation/depth controls, but no parent-owned scope/network/spend envelope is claimed. | A non-worker-editable authority envelope must intersect sandbox, repository/read scope, network, actions, remaining token/dollar/runtime budgets, expiry, and replay identity before any child worktree or model call. |

Deferred entries stay intentionally visible here rather than being converted
into a pile of duplicate research issues. A later weekly proposal should promote
one only when it supplies changed evidence, an owner-sized implementation slice,
and the residual acceptance criterion above.
